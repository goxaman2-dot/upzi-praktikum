# AI-прокси практикума (Cloudflare Worker)

Прокси хранит API-ключи нейросетей у Cloudflare. В `index.html`, опубликованный на GitHub Pages, ключи не попадают: страница знает только адрес прокси. Через прокси работает панель «Синтетическая экспертная панель (нейросети)» на занятии 8 (метод Дельфи).

## Развёртывание (один раз, около 15 минут, без командной строки)

1. Зарегистрироваться на dash.cloudflare.com (бесплатный тариф: 100 000 запросов в сутки).
2. **Workers & Pages → Create → Create Worker.** Имя, например `upzi-ai`. Нажать **Deploy**.
3. **Edit code.** Удалить шаблонный код, вставить целиком содержимое `worker.js` из этой папки, нажать **Deploy**.
4. **Settings → Variables and Secrets → Add.** Для каждого ключа выбрать тип **Secret**:

   | Имя | Что вставить |
   |---|---|
   | `DEEPSEEK_KEY` | ключ с platform.deepseek.com |
   | `QWEN_KEY` | ключ Alibaba Model Studio (DashScope, международный) |
   | `CLAUDE_KEY` | ключ с console.anthropic.com |
   | `GEMINI_KEY` | ключ с aistudio.google.com |
   | `GIGACHAT_AUTH` | «Ключ авторизации» из кабинета GigaChat API (строка Base64) |
   | `ACCESS_CODE` | код для студентов, например `skfu2026` (необязательно, но желательно) |

   Добавлять все ключи не обязательно: какие заданы, те нейросети и включатся. Остальные в панели будут серыми с пометкой «нет ключа у преподавателя».
5. Скопировать адрес воркера вида `https://upzi-ai.<ваше-имя>.workers.dev`.
6. В `index.html` найти строку `const AI_PROXY_URL = '';` и вставить адрес между кавычками. Закоммитить и запушить через GitHub Desktop.
7. Проверка: открыть в браузере `https://upzi-ai.<ваше-имя>.workers.dev/status`. В ответе в поле `configured: true` должны стоять те нейросети, ключи которых добавлены.

Код доступа `ACCESS_CODE` сообщается студентам устно на паре. Без него прокси отвечает отказом, поэтому посторонний, нашедший адрес в коде страницы, не израсходует ваш баланс. Код можно поменять в любой момент в тех же настройках Cloudflare, и править `index.html` для этого не нужно.

## Необязательные настройки (тип Text)

- `RATE_LIMIT`: сколько запросов принимать с одного IP за 10 минут. По умолчанию 300: в компьютерном классе все машины часто выходят в интернет через один IP, а группа из 20 человек за пару делает до 200 запросов (2 таблицы × 5 нейросетей на студента).
- `ALLOWED_ORIGINS`: с каких сайтов принимать запросы. По умолчанию это `https://goxaman2-dot.github.io,null`, где `null` разрешает работу из локально открытого файла.
- `CLAUDE_MODEL`, `QWEN_MODEL`, `DEEPSEEK_MODEL`, `GEMINI_MODEL`, `GIGACHAT_MODEL`: замена модели по умолчанию без правки кода.

## Известные ограничения (проверить после развёртывания)

- **GigaChat.** Серверы Сбера используют сертификат Национального удостоверяющего центра Минцифры. Cloudflare может не принять его, тогда в панели появится ошибка соединения у GigaChat. В этом случае GigaChat придётся держать на другом прокси, например в Yandex Cloud Functions. Остальные нейросети это не затрагивает.
- **Claude и Gemini.** Их API отказывают запросам из регионов, где сервис не поддерживается. Воркер выполняется в ближайшем к пользователю дата-центре Cloudflare, поэтому результат зависит от маршрута. Проверяется одним запросом через панель.
- **Доступность Cloudflare из России.** Если домен `workers.dev` в аудитории открывается медленно или не открывается вовсе, тот же `worker.js` с минимальными правками разворачивается в Yandex Cloud Functions.
- Лимит запросов считается в памяти одного экземпляра воркера. Это защита от случайного цикла или чужого скрипта, а не строгая квота. Строгий потолок расходов задаётся в кабинете каждого провайдера.
